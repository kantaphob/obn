# Datahaus

ระบบหลังบ้าน CRUD สำหรับจัดการรายการข้อมูลทั่วไป พัฒนาด้วย Next.js 16, Prisma ORM 7 และ SQLite

## เริ่มใช้งาน

ต้องใช้ Node.js 20.19 ขึ้นไป

```bash
npm install
cp .env.example .env
npm run db:migrate
npm run db:generate
npm run dev
```

เปิด [http://localhost:3000](http://localhost:3000) เพื่อใช้งานระบบ ฐานข้อมูล SQLite จะถูกสร้างเป็น `dev.db` ที่โฟลเดอร์โปรเจกต์

## คำสั่งฐานข้อมูล

- `npm run db:migrate -- --name ชื่อการเปลี่ยนแปลง` สร้างและใช้ migration
- `npm run db:generate` สร้าง Prisma Client หลังแก้ schema
- `npm run db:studio` เปิด Prisma Studio

## API

- `GET /api/entries` อ่านรายการ และกรองด้วย `q`, `category`, `status` ได้
- `POST /api/entries` สร้างรายการ
- `PATCH /api/entries/:id` แก้ไขรายการ
- `DELETE /api/entries/:id` ลบรายการ
- `GET /api/entries/export` ดาวน์โหลดข้อมูลเป็น CSV

โมเดลเริ่มต้นมีชื่อรายการ หมวดหมู่ รายละเอียด และสถานะ ปรับเพิ่มตารางและความสัมพันธ์ได้ที่ `prisma/schema.prisma`

> การตั้งค่านี้ใช้ SQLite ในเครื่องและยังไม่มีระบบเข้าสู่ระบบ ควรเพิ่มการยืนยันตัวตนและใช้ฐานข้อมูลที่รองรับงานจริงก่อนเปิดให้ผู้ใช้อื่นเข้าถึงหรือ deploy

## ข้อมูลรหัสไปรษณีย์

เปิด `/admin/postcode` เพื่อค้นหารหัสไปรษณีย์หรือชื่อพื้นที่ภาษาไทย/อังกฤษ กรองจังหวัดและอำเภอ และแบ่งหน้าได้

ติดตั้งตารางและนำเข้าข้อมูล:

```bash
npm run db:deploy
npm run db:generate
npm run db:import-postcodes
```

ข้อมูลต้นทางจาก `province.sql.pg`, `district.sql.pg`, `subdistrict.sql.pg` ที่ผู้ใช้ให้มา ถูกจัดเก็บเป็น `prisma/data/thailand-postcodes.json` จำนวน 77 จังหวัด 928 อำเภอ และ 7,433 ตำบล จึงนำเข้าได้โดยไม่ต้องเข้าถึงไฟล์ต้นฉบับบนเครื่องเดิม คำสั่งนำเข้าใช้ transaction และ upsert ตามรหัสพื้นที่ เรียกซ้ำได้โดยไม่เพิ่มข้อมูลซ้ำ ค่า `name_en` ที่เป็น NULL แปลงเป็นข้อความว่าง ส่วนพิกัดและรหัสไปรษณีย์ที่ไม่มีข้อมูลคงเป็น NULL (มี 10 ตำบลไม่มีรหัสไปรษณีย์) ข้อมูลนี้สะท้อนชุดไฟล์ที่ให้มา ไม่ได้อัปเดตจากแหล่งภายนอก

โมเดล Prisma: `Province` → `District` → `Subdistrict` โดยรหัสไปรษณีย์เก็บใน `Subdistrict.postcode` เป็นข้อความและอาจซ้ำกันหลายตำบล

### API สำหรับเรียกใช้จากหน้าอื่น

`GET /api/postcodes` รองรับ:

- `q`: ค้นหาชื่อไทย/อังกฤษหรือรหัสไปรษณีย์ ไม่เกิน 120 ตัวอักษร
- `postcode`: รหัสไปรษณีย์ตรงตัว 5 หลัก
- `provinceId`, `districtId`: กรองรหัสจังหวัดและอำเภอ
- `page`: หน้าที่ต้องการ เริ่มจาก 1
- `pageSize`: จำนวนต่อหน้า ค่าเริ่มต้น 25 สูงสุด 100

ตัวอย่าง `/api/postcodes?postcode=10200` หรือ `/api/postcodes?provinceId=10&districtId=1001&pageSize=50`

ผลลัพธ์เป็น `{ items, total, page, pageSize, totalPages, provinces, districts }` โดย `items` มีข้อมูลตำบล รหัสไปรษณีย์ พิกัด และ `district.province` ส่วน `districts` เป็นตัวเลือกอำเภอของจังหวัดที่ระบุ ค่าเลขไม่ถูกต้องจะได้ HTTP 400 และหน้าที่เกินขอบเขตจะถูกปรับเป็นหน้าสุดท้าย

## หน่วยนับและวัสดุอ้างอิง

- `/admin/unit`: หน่วย 64 รายการใน 10 หมวดหมู่ ค้นหารหัส ชื่อไทย/อังกฤษ และสัญลักษณ์ได้
- `/admin/material`: วัสดุก่อสร้างและตกแต่ง 111 รายการใน 10 หมวดหมู่ พร้อมหน่วยแนะนำ ทั้งสองหน้ากรองหมวดหมู่และแบ่งหน้าได้

แหล่งข้อมูลที่ตรวจและนำเข้าเมื่อ 13 ตุลาคม 2026:

- หน่วย: [UN/ECE Recommendation 20 และ Recommendation 21 ผ่าน Peppol](https://docs.peppol.eu/poacc/billing/3.0/codelist/UNECERec20/) — รายการ Revision 11e ใน Peppol May 2026; รหัสบรรจุภัณฑ์ Rec. 21 ใช้ X นำหน้าตาม Peppol
- วัสดุ: [CPV จาก TED / Publications Office of the EU](https://docs.ted.europa.eu/eforms/latest/reference/code-lists/cpv.html) — รหัส CPV 2008 จำนวน 8 หลัก ไม่รวม check digit

เป็นชุดรายการที่คัดเลือกสำหรับใช้งานทั่วไป ไม่ใช่รายการทั้งหมดในมาตรฐาน รหัสและชื่ออังกฤษตรงกับรายการต้นทาง ชื่อไทย หมวดหมู่ ตัวย่อแสดงผล และหน่วยแนะนำเป็นข้อมูลที่จัดทำเพิ่มเติมสำหรับแอป หน่วยแนะนำไม่ได้กำหนดโดย CPV และต้องเลือกให้เหมาะกับสินค้าจริง ถุง กล่อง ม้วน และพาเลตไม่มีอัตราแปลงตายตัว ข้อมูลนี้ไม่รวมราคา สต็อก หรือข้อกำหนดรับรองคุณภาพวัสดุ

นำเข้าบนเครื่องอื่นหรือหลังตั้งฐานข้อมูลใหม่:

```bash
npm run db:deploy
npm run db:generate
npm run db:import-catalogs
```

เก็บชุดอ้างอิงไว้ใน `prisma/data/reference-catalogs.json` พร้อม URL และรุ่นของแหล่งข้อมูล ไม่ต้องเชื่อมต่ออินเทอร์เน็ตเพื่อนำเข้า คำสั่ง import ใช้ transaction และ upsert ตามรหัสเดิม เรียกซ้ำได้โดยไม่สร้างรายการซ้ำ และอัปเดตค่าของรหัสที่มีในชุดอ้างอิง คำสั่งนี้ไม่ลบรายการนอกชุดนำเข้า

โมเดล Prisma คือ `Unit` และ `Material` โดย `Material.recommendedUnitCode` เชื่อมกับ `Unit.code` และเว้นว่างได้หากต้องเลือกหน่วยตามสินค้า

### API

- `GET /api/units`
- `GET /api/materials`

ทั้งสอง API รองรับ `q` (สูงสุด 120 ตัวอักษร), `category` (ชื่อหมวดตรงตัว), `code` (รหัสตรงตัว), `page` และ `pageSize` (ค่าเริ่มต้น 25, สูงสุด 100) ส่วนวัสดุรองรับ `unitCode` เพื่อกรองหน่วยแนะนำเพิ่มเติม รหัสหน่วยใช้ตัวพิมพ์ใหญ่ตามมาตรฐาน

ตัวอย่าง:

```text
/api/units?code=KGM
/api/units?q=metre
/api/materials?q=cement
/api/materials?code=44114100
/api/materials?unitCode=KGM&pageSize=50
```

ผลลัพธ์ `{ items, categories, total, totalRecords, page, pageSize, totalPages }` โดย `total` นับรายการหลังกรอง, `totalRecords` นับรายการทั้งหมด และ `categories` เป็นทุกหมวดในตาราง `items` มี `sourceUrl`, `sourceVersion`, `sourceDate` และวัสดุมี `recommendedUnit` ที่ประกอบด้วย `code`, `nameTh`, `symbol` หรือเป็น null

## ลักษณนามภาษาไทย

หน้า `/admin/classifier` แสดงลักษณนามทั่วไป 45 รายการใน 8 หมวดหมู่ เช่น ชิ้น อัน หลัง เส้น และชุด พร้อมคำอธิบายอังกฤษและตัวอย่างการใช้ ค้นหาจากตัวอย่างสิ่งของได้ เช่น `เชือก` จะแสดง `เส้น` เมนูข้อมูลหลักใช้ชื่อ “ลักษณนาม”

ข้อมูลคัดเลือกสำหรับระบบตามแนวทางการใช้ลักษณนามของ [สำนักงานราชบัณฑิตยสภา](https://www.orst.go.th/iwfm_table.asp?a=36&i=0040002104011001%2F63ERK0729009) ไม่ใช่การนำเข้าพจนานุกรมทางการทั้งหมด รหัส `CL001` เป็นต้นไปเป็นรหัสภายในแอป หมวดหมู่ คำอธิบายอังกฤษ และประโยคตัวอย่างจัดทำเพิ่มเติม การเลือกลักษณนามขึ้นอยู่กับคำนามและบริบท

```bash
npm run db:deploy
npm run db:generate
npm run db:import-classifiers
```

ชุดข้อมูลอยู่ใน `prisma/data/classifiers.json` นำเข้าซ้ำด้วย transaction และ upsert ได้โดยไม่สร้างข้อมูลซ้ำ โมเดล Prisma คือ `Classifier` ซึ่งมี `code`, `nameTh`, `nameEn`, `category`, `examples` และข้อมูลอ้างอิง

`GET /api/classifiers` รองรับ `q`, `category`, `code`, `page`, `pageSize` และส่งโครงสร้างเดียวกับ API หน่วย/วัสดุ (`items`, `categories`, `total`, `totalRecords`, `page`, `pageSize`, `totalPages`) ค่าเริ่มต้น 25 รายการต่อหน้า สูงสุด 100 ตัวอย่าง `/api/classifiers?code=CL015` หรือเรียกด้วย `URLSearchParams({ q: 'เชือก' })` เพื่อเข้ารหัสคำค้นภาษาไทย

## CRUD ข้อมูลหลัก

หน้า `/admin/material`, `/admin/unit`, `/admin/classifier` เพิ่ม แก้ไข และลบได้ผ่านปุ่มในตาราง มีฟอร์มตรวจข้อมูล ข้อความแจ้งผล และหน้าต่างยืนยันลบ หมวดหมู่เลือกจากรายการเดิมหรือพิมพ์ใหม่ได้ วัสดุเลือกหน่วยแนะนำจากฐานข้อมูลหน่วยนับ

API สำหรับแต่ละชุด (`units`, `materials`, `classifiers`):

- `POST /api/{ชุดข้อมูล}` สร้างรายการ (HTTP 201)
- `GET /api/{ชุดข้อมูล}/{code}` อ่านรายการเดียว
- `PATCH /api/{ชุดข้อมูล}/{code}` แก้ไขเฉพาะฟิลด์ที่ส่งมา
- `DELETE /api/{ชุดข้อมูล}/{code}` ลบรายการ (HTTP 204)

ฟิลด์ร่วม: `code`, `nameTh`, `nameEn`, `category` โดยรหัส ชื่อไทย และหมวดหมู่จำเป็น รหัสไม่เกิน 32 ตัวอักษร ใช้ A–Z, 0–9, `-`, `_` และคงเดิมเมื่อแก้ไข ชื่ออังกฤษเว้นว่างได้ รหัสวัสดุใหม่ใช้รหัสภายใน เช่น MAT001 ได้ ข้อมูลเริ่มต้นยังเก็บรหัส CPV

หน่วยต้องมี `symbol` และระบุ `standard` ได้ ลักษณนามต้องมี `examples` วัสดุระบุ `recommendedUnitCode` หรือ null ได้ ระบบส่ง HTTP 400 เมื่อข้อมูลไม่ถูกต้อง, 404 เมื่อไม่พบรายการ, 409 เมื่อรหัส/ชื่อลักษณนามซ้ำ หรือเมื่อพยายามลบหน่วยที่วัสดุยังอ้างอิงอยู่ การแก้ไข/เพิ่มผ่านระบบจะระบุใน `sourceVersion` และบันทึกวันที่ใน `sourceDate`

คำสั่ง import ชุดอ้างอิงยังใช้ upsert จึงเขียนค่าจากไฟล์ทับรหัสเดิมที่ผู้ใช้แก้ไขได้ เมื่อต้องการรักษาข้อมูลที่แก้ไข ควรใช้ CRUD ในหน้าเว็บสำหรับการจัดการรายวัน
# ข้อมูลธนาคาร

หน้า `/admin/banking` อ่านและจัดการข้อมูลจากโมเดล `Banking` ในฐานข้อมูล รองรับค้นหา เพิ่ม แก้ไข และยืนยันก่อนลบ รหัสธนาคารเป็นข้อความตัวเลข 3 หลักและห้ามซ้ำ

ติดตั้งข้อมูลเริ่มต้น 18 ธนาคารตามรายการที่ให้ไว้:

```sh
npm run db:deploy
npm run db:generate
npm run db:import-banks
```

ตัวนำเข้าข้ามรหัสที่มีอยู่แล้ว จึงไม่เขียนทับข้อมูลที่แก้ไขในระบบ ฟิลด์ `bankFull` เก็บชื่ออังกฤษเดียวกับ `bankNameEN`

API: `GET /api/banking`, `POST /api/banking`, `GET /api/banking/:id`, `PATCH /api/banking/:id`, `DELETE /api/banking/:id` โดย POST และ PATCH รับ `bankCode`, `bankShort`, `bankNameTH`, `bankNameEN` ครบทั้ง 4 ฟิลด์


## สิ่งของและสินค้า

หน้า `/admin/things` ใช้ตาราง `Entry` ที่มีอยู่แล้ว ผ่าน `GET/POST /api/entries` และ `PATCH/DELETE /api/entries/:id` รองรับชื่อรายการ หมวดหมู่ รายละเอียด สถานะใช้งาน/เก็บถาวร ค้นหา กรองสถานะ และยืนยันก่อนลบ เมื่อบันทึกสำเร็จจะโหลดข้อมูลจากฐานข้อมูลใหม่ ไม่มีข้อมูลตัวอย่างเพิ่มอัตโนมัติ

## อ่านบัตรผู้กู้และ OCR

- เปิดฟอร์มเพิ่ม/แก้ไขผู้กู้แล้วระบบตรวจบัตรทุก 3 วินาที และเติมข้อมูลเมื่อพบข้อมูลบัตรใหม่ โดยไม่บันทึกผู้กู้เอง
- เมื่อเว้น `AISC_SMARTCARD_API_URL` ระบบอ่านบัตรประชาชนไทยผ่าน PC/SC โดยตรง (ต้องมีเครื่องอ่านที่ระบบมองเห็นและติดตั้ง native dependency สำเร็จ) หากใช้ AISC-compatible reader service ให้ตั้ง URL ที่คืนข้อมูลบัตรเป็น JSON (หรือ `{ data: ... }`) และตั้ง `AISC_SMARTCARD_API_TOKEN` หาก service ต้องใช้ token
- ปุ่ม OCR รับภาพ JPG/PNG/WebP ไม่เกิน 5 MB อ่านภาษาไทยและอังกฤษด้วย Tesseract.js ในเบราว์เซอร์ การใช้งานครั้งแรกต้องมีอินเทอร์เน็ตเพื่อโหลด worker และโมเดลภาษา ภาพต้นฉบับเก็บในระบบผ่าน API รูปภาพ
- OCR เติมเฉพาะช่องที่แยกได้และแสดงข้อความต้นฉบับให้ตรวจสอบ ความแม่นยำขึ้นอยู่กับความชัดเจนของภาพ ไม่ครอปรูปบุคคลจากภาพบัตรอัตโนมัติ

## รับชำระและประวัติสัญญา

เปิด `/dashboard/loan/payments` หรือเมนู “รับชำระและประวัติ” เพื่อเลือกสัญญาและบันทึกยอดรับชำระ สัญญาต้องอยู่ในสถานะ ACTIVE หรือ OVERDUE รายการจะตัดดอกเบี้ยค้างก่อน ตามด้วยยอดเพิ่มหลังครบกำหนด และเงินต้น

- ดอกเบี้ยรายเดือนคิดจากเงินต้นเริ่มต้นในแต่ละรอบเดือนจากวันเริ่มสัญญา จนถึงวันครบกำหนด (ไม่ทบเป็นเงินต้น) หยุดคิดรายเดือนเมื่อเงินต้นถูกชำระครบ
- หลังวันครบกำหนด เพิ่มตาม lateFeePerDay ของสัญญา (ตั้งต้น 50 บาท/วัน) จนปิดยอด หาก lateFeeWaived เปิดจะไม่เพิ่มยอดส่วนนี้
- แบบหักดอกล่วงหน้าไม่มีดอกเบี้ยเรียกเก็บซ้ำ แบบตามสัญญาไม่หักดอกจะคิดดอกที่ตกลงในสัญญา
