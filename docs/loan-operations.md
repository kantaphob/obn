# งานสินเชื่อและบัญชีทุน

## หน้าที่เพิ่ม
- `/dashboard/loan/schedules`: งวดรายสัญญา แยกต้น/ดอก จ่ายบางส่วน และส่งออก CSV
- `/dashboard/loan/calendar`: ปฏิทินงวดและวันนัดติดตาม
- `/dashboard/loan/collections`: ผลติดต่อ ผู้รับผิดชอบ วันนัด ยอดนัด และอายุหนี้ตามงวด
- `/dashboard/loan/borrower-overview`: ยอดปิด ณ วันที่เลือก สัญญา เอกสาร งวด รับชำระ และประวัติติดตาม
- `/dashboard/loan/capital-account`: ผู้ลงทุน เพิ่มทุน/ถอนทุนผ่านคำขออนุมัติ และประวัติทุน
- `/dashboard/loan/profit`: ผลดำเนินงานรายเดือน/ปี และรายรับที่ผูกกับสัญญา
- `/dashboard/loan/forecast`: คาดการณ์ 7/30/90 วัน และแผนรับ–จ่ายเพิ่มเติม
- `/dashboard/loan/accounting`: กระทบยอด ปิด/เปิดรอบ ตรวจรายการซ้ำ และกลับรายการ

ทุกหน้าดึงข้อมูลใหม่ทุก 10 วินาทีเมื่อแท็บแสดงอยู่ และดึงทันทีเมื่อกลับเข้าแท็บ

## วิธีเริ่มใช้งาน
1. บัญชีทุน: เพิ่มทะเบียนผู้ลงทุน แล้วระบุผู้ลงทุนให้รายการทุนเดิมที่ยังไม่จัดสรร (ต้องเปิดรอบบัญชีนั้นก่อน)
2. ส่งคำขอเพิ่มทุนหรือถอนทุน ระบุบริษัท ช่องทาง และเลขอ้างอิงการโอน
3. ผู้อนุมัติตรวจและอนุมัติเมื่อรับ/จ่ายเงินจริง ระบบบันทึกสมุดบัญชีด้วยวันที่อนุมัติ ไม่ลงบัญชีซ้ำจากหน้าสมุดบัญชี
4. ตรวจตารางงวดและปฏิทิน กดรับชำระเพื่อเปิดแบบรับชำระเดิมพร้อมผู้กู้และสัญญา
5. บันทึกการติดตามและนัดชำระ สถานะตามนัดเทียบกับยอดรับที่บันทึกหลังบันทึกติดตาม
6. กระทบยอดก่อนปิดรอบ หากแก้ไขย้อนหลังให้ผู้อนุมัติเปิดรอบและระบุเหตุผล

## สิทธิ์
API อ่านชุดงานต้องมี `contracts:read` และ `accounting:read` (สิทธิ์ write ใช้อ่านได้ด้วย)
- ติดตามหนี้: `contracts:write`
- ทะเบียนผู้ลงทุน คำขอทุน แผนเงินสด และกระทบยอด: `accounting:write`
- อนุมัติทุน ปิด/เปิดรอบ กลับรายการ และจัดสรรทุนเดิม: `accounting:write` + `loan:approve`
- เจ้าของระบบที่มี `*` ทำได้ทั้งหมด และอนุมัติคำขอของตนเองได้
- ผู้อนุมัติทั่วไปต้องไม่ใช่ผู้ส่งคำขอทุนเดียวกัน
- ข้อมูลและรายการใหม่กรองบริษัทตามสิทธิ์ที่กำหนด

## หลักการคำนวณ
- จำนวนเงินเป็นสตางค์ทั้งหมด ใช้ `loanBalance` ร่วมกับหน้ารับชำระ
- งวดแจกแจงการชำระเงินต้น/ดอกเบี้ยตามลำดับงวด โดยไม่บวกใบรับซ้ำกับรายการตัดชำระ
- ยกเว้นค่าปรับไม่ทำให้จำนวนวันเกินกำหนดเป็นศูนย์
- ทุนสุทธิ = เพิ่มทุน − ถอนทุน ไม่ใช่เงินสดตามบัญชี
- ผลดำเนินงานค่าเริ่มต้น = ดอกเบี้ยรับ + ค่าปรับรับ + รายได้อื่น − ค่าใช้จ่ายดำเนินงาน
- เงินทุน เงินต้นรับคืน และเงินปล่อยกู้ไม่รวมเป็นรายได้ดำเนินงาน
- ดอกหักล่วงหน้าแสดงแยก ตัวเลือกในรายงานรวมทั้งจำนวนในเดือนจ่ายกู้เป็นมุมมองบริหาร ไม่ใช่การทยอยรับรู้ตามอายุสัญญา และไม่เพิ่มยอดเงินสด
- เงินรับเก่าที่แยกต้น/ดอกไม่ได้แสดงคำเตือน ยังไม่จัดเป็นรายได้
- รายสัญญาแสดงเฉพาะรายการที่ผูกสัญญา ไม่ปันส่วนค่าใช้จ่ายกลางโดยอัตโนมัติ
- คาดการณ์รวมงวดตั้งแต่วันนี้ถึงวันเป้าหมาย แผนเงินสด และสัญญารอจ่าย ไม่สมมติว่าจะเก็บหนี้เก่าที่เลยกำหนดได้
- แผนเงินสดไม่สร้างรายการเงินจริง เมื่อบันทึกเงินจริงแล้วให้นำแผนออกเพื่อไม่ให้นับซ้ำ
- รายการกระทบยอดช่องทางโอนรวมทุกบัญชีธนาคารของบริษัท ต้องใช้ยอดจริงที่ครอบคลุมขอบเขตเดียวกัน

## การรักษาประวัติ
- ไม่ลบรายการสมุดบัญชี ใช้กลับรายการในวันที่รอบยังเปิดอยู่
- รายการกลับบัญชีมีรหัสอ้างอิงรายการเดิมและผู้ทำรายการ จัดหมวดเป็นจำนวนติดลบของประเภทเดิมในรายงานรายได้/ทุน
- กลับใบรับชำระได้จากใบรับล่าสุดที่ยังไม่กลับของสัญญา เพิ่มรายการตัดชำระติดลบเพื่อคืนยอดหนี้ และสร้างรายการเงินจ่ายกลับในสมุดบัญชี
- สัญญาที่มีใบรับกลับรายการแล้วไม่แก้เงื่อนไขย้อนหลัง เพื่อรักษาการจัดสรรเงินเดิม
- ถอนทุนไม่เกินเงินสดของบริษัทและทุนสุทธิของผู้ลงทุนที่ระบุ
- รอบปิดป้องกันรับชำระ จ่ายกู้ บันทึก/แก้บัญชี และแก้เงื่อนไขที่กระทบรายการในรอบ

## ข้อจำกัดของข้อมูลย้อนหลัง
การเลือกวันที่คำนวณจากวันที่รายการเงินและประวัติที่มีอยู่ ไม่สามารถสร้างข้อมูลเงื่อนไขสัญญาหรือข้อมูลที่ถูกลบก่อนมีระบบบันทึกประวัติขึ้นมาใหม่ได้ รายการทุนเก่าที่ไม่มีผู้ลงทุนต้องจัดสรรก่อนใช้ยอดทุนรายบุคคล

## สรุปปิดรอบบน Dashboard
- Dashboard หลักและ Overview Loan แสดงรอบล่าสุดแยกบริษัท พร้อมเงินสดปัจจุบันและส่วนต่างจากยอดตอนปิด
- รอบใหม่เก็บยอดรับ/จ่ายในรอบ เงินสดสะสม ณ วันปิด และผลต่างกระทบยอดเป็น snapshot ในธุรกรรมเดียวกับการปิดรอบ
- รายรับ/จ่ายในรอบเริ่มหลังวันปิดรอบก่อนหน้า หากยังไม่มีรอบก่อนหน้าใช้ตั้งแต่รายการแรก
- ผลกระทบยอดใช้ยอดจริงแบบทุกช่องทางของบริษัทในวันปิด หากไม่มีจะแสดงรอตรวจสอบ
- เปิดรอบจากรอบล่าสุดก่อน ยอด snapshot เดิมยังอยู่เป็นประวัติ เมื่อปิดใหม่จะมี snapshot ใหม่
- รอบเก่าที่ไม่มี snapshot ไม่สร้างยอดยืนยันย้อนหลังแทนข้อมูลที่ไม่เคยบันทึก
- ยอดแต่ละบริษัทอาจมีวันปิดต่างกัน จึงแสดงแยกบริษัท ไม่รวมเป็นยอดยืนยัน ณ วันเดียวกัน

## การแก้หลังตรวจความถูกต้อง (20 ต.ค. 2569)
- สูตร MONTHLY_FLAT คิดดอกเมื่อครบงวดปลายเดือน ใช้ยอดดอกทั้งสัญญาที่บันทึกไว้ แบ่งเป็นสตางค์และเก็บเศษไว้ในงวดสุดท้าย
- วันครบกำหนดของแบบผ่อนต้องตรงวันครบงวดสุดท้าย เพื่อให้ตารางและสูตรยอดหนี้ตรงกัน
- การเปลี่ยนรูปแบบดอกก่อนจ่ายเงินปรับ netDisbursed และสร้างตารางใหม่ในธุรกรรมเดียว
- ปิดก่อนกำหนดแสดง paid ตามเงินจริง และแยกยอดงวดที่เหลือเป็น SETTLED/ยอดยกเว้น ไม่อ้างว่าเก็บเงินจริงแล้ว
- หน้ารายการสัญญาใช้สถานะแสดงผลตามวันปัจจุบัน ไม่เขียนสถานะลงฐานข้อมูลจาก GET
- ใช้ตัวตรวจบริษัทกลางกับสัญญา รับชำระ จ่ายกู้ ร่าง เอกสาร ประวัติ และ Dashboard
- บัญชีที่ถูกจำกัดบริษัทจะไม่เห็นสัญญาที่ยังไม่ระบุบริษัท ต้องให้เจ้าของระบบยืนยันการจัดสรรในหน้ากระทบยอดก่อน
- เจ้าของระบบที่ดูข้อมูลรวมสามารถระบุบริษัทและสาขาให้สัญญา/รายการบัญชีเดิมได้ พร้อมเหตุผลและประวัติการจัดสรร
- ไม่ปิดรอบขณะมีรายการเงิน Loan ในวันปิดที่ยังไม่จัดสรรบริษัท เพื่อป้องกันการรับรองยอดไม่ครบ
- คำสั่งตรวจซ้ำ: `npm run check:loan` (ข้อมูลจำลอง ไม่มีการบันทึกธุรกรรมจริง)
